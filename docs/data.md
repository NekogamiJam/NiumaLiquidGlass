# Data and generated assets

## Rime input data

`input-data/` contains the Niuma four-code dictionaries. `app/src/main/assets/shared/` contains the packaged copy used by the Android app, along with `niuma_glass.schema.yaml`, `niuma_glass.trime.yaml`, Lua processing code, and OpenCC data. The keyboard's candidates and code hints are generated by the Rime schema and dictionary tables; do not modify a packaged copy without updating its source and contract tests.

## Derived data

- `association-tools/build_associations.py` produces association candidates from the pinned source data.
- `gesture-tools/build_z_transitions.py` produces Z-prefix transition metadata from the pinned debug fixture and input tables.
- `stage-*.py` helpers copy project data and assets into the Android source tree; manifests in `vendor/` and `offline-asr/` record ownership and hashes.
- `app/src/main/assets/checksums.json` records packaged asset integrity.

## Binary inputs

Large speech models and prebuilt native libraries are excluded from Git and listed in `tools/binaries.json`. Restore them using `tools/fetch-binaries.py`; each file is verified by SHA-256. The smaller Chime model and data are shipped with their notice files, revision and hash metadata.

## Privacy boundaries

Device snapshots, app settings, personal test records, signing material, generated build output, and machine-local reports are not part of this public source tree. Runtime probes that require a desktop Rime install must be pointed to a local directory using `NIUMA_RIME_DLL_DIR`.
